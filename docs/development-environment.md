# Dagana — Local Development Environment

## 1. Purpose

Use Docker Compose to make the API runtime, PostgreSQL, and Redis consistent across development machines. This configuration is **local development only**. It is not a production deployment recipe.

Initial runtime baseline: PHP 8.5 (compatible with a new Laravel 13 application), PostgreSQL 18, and Redis 7. Keep the Laravel major version explicitly pinned in the application dependency file once the project is scaffolded, and update runtime major versions deliberately with the test suite passing; do not use floating dependencies as a substitute for version management.

Reference documentation: [Laravel release/support policy](https://laravel.com/docs/releases), [PHP supported versions](https://www.php.net/supported-versions.php), and the [official PostgreSQL Docker image documentation](https://github.com/docker-library/docs/blob/master/postgres/content.md). PostgreSQL 18 changes the official image’s persistent volume root to `/var/lib/postgresql`; this Compose file mounts the named volume there. Do not change it to the older `/var/lib/postgresql/data` path unless deliberately switching back to a pre-18 image.

The starter configuration assumes this repository layout:

```text
.
├── AGENTS.md
├── PRD-Dagana.md
├── compose.yaml
├── .env.docker.example
├── docker/
│   └── php/
│       └── Dockerfile.dev
├── apps/
│   ├── api/             # Laravel API
│   ├── admin-web/       # React + TypeScript (initialize later)
│   ├── customer-web/    # React + TypeScript (initialize later)
│   └── pos/             # Flutter POS (host SDK initially)
└── docs/
```

If the actual repository uses another layout, update the Compose mount paths and docs together rather than duplicating application files to fit this template.

## 2. Prerequisites

- Docker Desktop with Docker Compose v2 (or Docker Engine + the Compose plugin).
- Git.
- An editor/IDE of choice.
- Optional host tooling: Node.js for React development and Flutter SDK plus an emulator/device for POS work. These are not required just to run API/PostgreSQL/Redis containers.

## 3. Environment configuration

Copy `.env.docker.example` to `.env.docker` and adjust ports if they conflict with services already running on the host. The provided passwords are disposable local defaults; never reuse them outside local development.

Linux/macOS/Git Bash:

```bash
cp .env.docker.example .env.docker
mkdir -p apps/api apps/admin-web apps/customer-web apps/pos
```

Windows PowerShell:

```powershell
Copy-Item .env.docker.example .env.docker
New-Item -ItemType Directory -Force apps/api, apps/admin-web, apps/customer-web, apps/pos
```

## 4. Initialize Laravel in the API workspace

If `apps/api` already contains a Laravel application, skip this step. Otherwise, from the repository root:

```bash
docker compose --env-file .env.docker build api
docker compose --env-file .env.docker run --rm --no-deps api composer create-project laravel/laravel .
```

The `api` service mounts `apps/api` into the container and includes Composer. Run the command only when that directory is empty; do not run `create-project` over an existing application.

Copy the Laravel environment template and configure the database/cache hosts for container networking:

```bash
cp apps/api/.env.example apps/api/.env
```

In `apps/api/.env`, ensure the relevant settings are equivalent to:

```dotenv
APP_ENV=local
DB_CONNECTION=pgsql
DB_HOST=postgres
DB_PORT=5432
DB_DATABASE=dagana
DB_USERNAME=dagana
DB_PASSWORD=dagana_local_only
CACHE_STORE=redis
QUEUE_CONNECTION=redis
SESSION_DRIVER=redis
REDIS_HOST=redis
REDIS_PORT=6379
SANCTUM_STATEFUL_DOMAINS=localhost:5173,127.0.0.1:5173,localhost:8000,127.0.0.1:8000
CORS_ALLOWED_ORIGINS=http://localhost:5173,http://127.0.0.1:5173
```

`SANCTUM_STATEFUL_DOMAINS` mendaftar origin SPA first-party yang menerima session cookie; `CORS_ALLOWED_ORIGINS` harus eksplisit karena CORS memakai kredensial (lihat ADR-0005).

Keep `APP_KEY` generated by Laravel. Do not commit `apps/api/.env`.

> The Compose service also supplies matching container environment variables for database/cache connectivity. If the local database credentials are changed in `.env.docker`, keep the values in `apps/api/.env` aligned or remove duplicate overrides consistently.

## 5. Start and work with the environment

```bash
docker compose --env-file .env.docker up -d --build
docker compose --env-file .env.docker ps
```

Once Laravel is initialized and the API container is running:

```bash
docker compose --env-file .env.docker exec api php artisan key:generate
docker compose --env-file .env.docker exec api php artisan migrate
```

Open the API at `http://localhost:8000`. If no Laravel `artisan` file exists yet, the API container intentionally stays idle and logs a reminder; PostgreSQL and Redis can still start.

Once the stack is running, verify connectivity:

```bash
curl http://localhost:8000/up
curl http://localhost:8000/api/v1/health
```

`/api/v1/health` returns `{"data":{"status":"ok","checks":{...}}}` and reports the database and cache connectivity.

### Autentikasi (SPA session, Phase 1)

The API uses Sanctum's stateful SPA mode (session cookie + CSRF), not Bearer tokens (ADR-0005). A browser client must send an `Origin` from `SANCTUM_STATEFUL_DOMAINS`. From a shell, add the `Origin` header so the request is treated as stateful:

```bash
# 1. Obtain a CSRF cookie (also sets XSRF-TOKEN)
curl -s -c cookies.txt -H 'Origin: http://localhost:5173' http://localhost:8000/sanctum/csrf-cookie

# 2. Register (or POST /api/v1/auth/login)
curl -s -b cookies.txt -c cookies.txt \
  -H 'Origin: http://localhost:5173' -H 'Accept: application/json' \
  -H 'Content-Type: application/json' \
  -d '{"name":"Owner Demo","email":"owner@dagana.test","password":"password123"}' \
  http://localhost:8000/api/v1/auth/register

# 3. Authenticated request (session cookie is reused)
curl -s -b cookies.txt -H 'Origin: http://localhost:5173' -H 'Accept: application/json' \
  http://localhost:8000/api/v1/me
```

CSRF is enforced for state-changing requests from browser clients; read (GET) requests do not require the token. In the test suite CSRF is bypassed automatically. To seed a demo owner/business/outlet locally, run `php artisan db:seed` (synthetic data only).

Useful commands:

```bash
# Follow service logs
docker compose --env-file .env.docker logs -f api postgres redis

# Run Laravel commands
docker compose --env-file .env.docker exec api php artisan test
docker compose --env-file .env.docker exec api php artisan route:list

# Install/update Composer dependencies in the mounted API workspace
docker compose --env-file .env.docker exec api composer install

# Stop containers but preserve local database data
docker compose --env-file .env.docker down
```

Do not use `docker compose down -v` casually: `-v` removes named volumes and can permanently delete local database data.

## 6. Host vs. container networking

- From the API container, PostgreSQL is `postgres:5432` and Redis is `redis:6379`.
- From the host, PostgreSQL is `localhost:${POSTGRES_PORT}` (default `54329`), Redis is `localhost:${REDIS_PORT}` (default `6380`), and the API is `http://localhost:${API_PORT}` (default `8000`).
- `localhost` inside a container refers to that same container, not the host and not another Compose service.

## 7. React and Flutter development

The initial Compose baseline focuses on the Laravel API, PostgreSQL, and Redis. Once React workspaces exist, either run their dev servers on the host or add opt-in Compose services using the repository's selected Node version and lockfile. Do not run `npm install` on every container start; use a persistent `node_modules` strategy and reproducible lockfile-based installs.

Flutter's SDK, Android emulator, USB device access, and platform build tools are generally simpler to keep on the host initially. The Flutter application still uses the containerized API through the host-accessible API URL. Emulator-specific hostnames may differ from `localhost`; document the chosen emulator/device route with the Flutter setup.

## 8. Data and reset policy

- PostgreSQL data persists in the named volume `dagana_postgres_data`, mounted at `/var/lib/postgresql` for PostgreSQL 18.
- `docker compose down` stops/removes containers and the network while preserving the named volume.
- Deleting volumes, resetting a database, or running destructive seed/reset commands requires an explicit decision and a clear warning.
- Use synthetic data only. Never import production/customer data into a shared development environment.
- A developer's local database is not a source of truth. Schema changes must be committed as migrations.

## 9. What this setup does not provide

This baseline does not configure production TLS, production secrets, a production web server, automated backups, horizontal scaling, hosted object storage, or a production queue/realtime stack. Add those through a separate deployment design once the target host and operational requirements are known.
